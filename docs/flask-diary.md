# Заметки: Flask Diary

## Задача
Веб-дневник с регистрацией, входом и личными карточками. Каждый пользователь работает только со своими данными.

## Ключевые решения
- **Изоляция данных на сервере.** Карточка хранит `user_id`, все запросы фильтруются по текущему пользователю. Для чужой карточки возвращается 404, а не 403: так не раскрывается сам факт её существования.
- **Изменяющие действия только через POST.** Удаление идёт через форму, а не по ссылке, чтобы его нельзя было вызвать переходом по адресу.
- **CSRF-защита для всех форм** (Flask-WTF). В тестах она по умолчанию выключена, а отдельный тест включает её и проверяет, что запрос без токена получает 400.
- **Поиск и пагинация** через `paginate()`: запрос ограничивается на уровне базы данных, а не в Python.

## Трудности и выводы
- **Тесты стирали рабочую базу.** Адрес базы подменялся в тестах уже после создания подключения, поэтому подмена не действовала, а `drop_all()` в конце теста очищал настоящую базу. Исправление: адрес базы читается из переменной `DATABASE_URL`, тесты задают её до импорта приложения. Вывод: конфигурацию, от которой зависит создание подключения, нужно менять до создания приложения.
- **Таблицы создавались только при прямом запуске.** Под gunicorn (Docker, хостинг) блок `if __name__ == "__main__"` не выполняется, и приложение стартовало бы без таблиц. Исправление: создание таблиц при импорте.
- **Доступность интерфейса.** Расчёт контраста показал, что плейсхолдер (2,2:1) и белый текст на части градиента кнопок (4,0:1) не проходят WCAG AA. Исправлено, плюс добавлены `viewport`, подписи полей, видимый фокус, ссылка «перейти к содержимому» и учёт `prefers-reduced-motion`.
- **Покрытие тестами** (около 99%) помогло найти непроверенные ветки: пустая регистрация и переходы форм.

## Что можно улучшить
- миграции базы (Flask-Migrate) вместо `create_all`;
- ограничение длины полей и более подробные сообщения валидации;
- ограничение числа попыток входа;
- PostgreSQL вместо SQLite для постоянного хранения на хостинге.
