# Заметки: CLI Shop

## Задача
Консольный магазин: каталог, корзина, четыре алгоритма сортировки. Упражнение на ООП и разделение ответственности.

## Ключевые решения
- **Разделение на модули:** модели (`Product`, `Catalog`), корзина, сортировки, интерфейс, хранилище. Логика не зависит от ввода-вывода: `input()` и `print()` остались только в слое интерфейса.
- **Сортировки получают функцию ключа** (`key_func`), поэтому один алгоритм работает по цене, весу и категории. Исходный список не изменяется.
- **Хранение в JSON** (`data/catalog.json`): если файл отсутствует или повреждён, программа загружает стандартный каталог и предупреждает, а не падает.

## Трудности и выводы
- **Проверка сортировок.** Лучший способ — сравнивать результат со встроенной `sorted()` по всем сочетаниям алгоритма, критерия и порядка (параметризованные тесты, 32 проверки). Заодно проверяются неизменность входа, пустой и одиночный списки.
- **Тесты интерфейса.** `input` подменяется заранее заданными ответами; через `conftest.py` тесты направлены во временную папку, чтобы не трогать настоящий файл данных.
- **Данные не должны попадать в репозиторий.** `data/` добавлена в `.gitignore`.

## Что можно улучшить
- перейти с JSON на SQLite;
- добавить веб-интерфейс на Flask поверх тех же классов;
- разделить `ShopApp` на логику и представление ещё строже, чтобы тестировать без подмены ввода.
