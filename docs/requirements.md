# Требования к Flask Diary

Документ фиксирует, что должна делать система и с какими качествами. Каждое требование связано с проверкой: либо автотестом, либо пунктом чеклиста.

## Назначение и аудитория

Flask Diary — веб-приложение для личных заметок в виде карточек. Аудитория: люди, которые ведут личные записи в браузере на компьютере или телефоне и хотят, чтобы чужие не видели их данные.

## Функциональные требования

| № | Требование | Проверка |
|---|---|---|
| FR-1 | Пользователь может зарегистрироваться по логину и паролю; повторный логин отклоняется | `test_auth.py::test_register_creates_user_in_db` |
| FR-2 | Пользователь может войти и выйти; выход выполняется только запросом POST | `test_auth.py::test_login_success_redirects_to_index`, `test_logout`, `test_logout_get_is_not_allowed` |
| FR-3 | Пользователь создаёт, просматривает, редактирует и удаляет свои карточки | `test_auth.py::test_edit_card_updates_data`, `test_delete_card_removes_it` |
| FR-4 | Карточки можно искать по заголовку, подзаголовку и тексту без учёта регистра | `test_auth.py::test_search_finds_matching_cards_only` |
| FR-5 | Список разбит на страницы по 6 карточек | `test_auth.py::test_pagination_splits_cards_between_pages` |
| FR-6 | Пользователь видит и может менять только свои карточки (чужие дают 404) | `test_auth.py::test_user_sees_only_own_cards`, `test_user_cannot_open_foreign_card` |
| FR-7 | После 5 неудачных входов вход блокируется на 5 минут (429) | `test_rate_limit.py::test_sixth_attempt_is_blocked_after_five_failures` |
| FR-8 | Ошибки показываются понятными страницами без технических подробностей | `test_errors.py::test_404_page_is_friendly`, `test_500_page_hides_error_details` |
| FR-9 | Есть адрес проверки работоспособности `/health` | `test_health.py::test_health_ok` |
| FR-10 | Удаление карточки требует подтверждения в доступном окне | `test_confirm_dialog.py::test_card_page_has_accessible_delete_dialog`; ручная проверка в браузере |

## Нефункциональные требования

| № | Область | Требование | Как проверяется |
|---|---|---|---|
| NFR-1 | Производительность | p95 ответа не более 300 мс при 20 одновременных пользователях на staging | `scripts/loadtest.py`; локально p95 7–8 мс при 800 запросов/с |
| NFR-2 | Доступность сервиса | не менее 99,5% в месяц; `/health` для мониторинга | внешняя проверка доступности (⬜ не настроена) |
| NFR-3 | Безопасность данных | пароли только в виде хеша; защита форм от CSRF; cookie `HttpOnly`, `SameSite`, `Secure` в боевом режиме | `test_auth.py::test_password_is_stored_as_hash`, `test_post_without_csrf_token_is_rejected`, `test_session_cookie_is_secure_when_enabled` |
| NFR-4 | Безопасность окружения | секреты только в переменных окружения; без надёжного `SECRET_KEY` приложение не запускается; отладка выключена | `test_config.py::test_production_rejects_missing_or_weak_key`; чеклист перед выкаткой |
| NFR-5 | Безопасность ввода | все данные проверяются на сервере; ограничена длина полей и размер запроса | `test_validation.py::test_register_short_password_is_rejected`, `test_oversized_request_is_rejected` |
| NFR-6 | Конфиденциальность журнала | в журнал не попадают пароли, токены и содержимое карточек | `test_logging.py::test_passwords_never_appear_in_logs` |
| NFR-7 | Доступность интерфейса | WCAG 2.1 AA: контраст не ниже 4,5:1, управление с клавиатуры, видимый фокус, подписи у полей | ручная проверка и расчёт контраста; автоматический аудит (⬜ Lighthouse) |
| NFR-8 | Адаптивность | работа без горизонтальной прокрутки от 375 px | ручная проверка |
| NFR-9 | Совместимость | две последние версии Chrome, Firefox, Safari, Edge; Python 3.12 и 3.14 | CI: матрица Python; браузеры проверяются вручную |
| NFR-10 | Надёжность данных | изменение схемы только миграциями с откатом; бэкап перед релизом | `test_migrations.py::test_migrations_match_models`; репетиция релиза |
| NFR-11 | Устойчивость к сбоям | страница ошибки не зависит от базы данных | `test_errors.py::test_500_page_renders_even_when_database_is_down` |
| NFR-12 | Восстановление | допустимая потеря данных не более 24 часов (RPO), время восстановления не более 2 часов (RTO) | ежедневный бэкап (⬜ на хостинге) и проверка восстановления раз в квартал |
| NFR-13 | Сопровождаемость | линтер и форматирование без замечаний, покрытие не ниже 95%, документация актуальна | CI: задачи `lint`, `flask-apps` |
| NFR-15 | Защита браузера | строгая политика содержимого (CSP) без встроенного кода, запрет встраивания в чужие страницы, запрет угадывания типа файлов, HSTS по HTTPS, личные страницы не кэшируются | `test_security_headers.py`, `test_csp_templates.py`; `curl -I` на боевом адресе |
| NFR-14 | Переносимость | запуск в Docker и без него; SQLite для разработки, PostgreSQL для боевой работы | CI: задачи `docker`, `diary-postgres` |

## Вне рамок (пока не делаем)

Восстановление пароля, подтверждение почты, роли и общий доступ к карточкам, REST API, вложения. Решение о добавлении принимается отдельно и оформляется как новое требование.

## Как менять требования

Новое или изменённое требование сначала записывается здесь (с проверкой), затем реализуется. Требование без проверки считается незавершённым.
